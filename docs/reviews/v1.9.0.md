# v1.9.0 Release Review

Status: **Release candidate**. This record covers the human-friendly local web entrypoints reviewed at exact
source `4f7089bcdd2000e6fc89304bf7168c1739846eca`. Publication evidence is recorded separately after merge and tag.

## Scope

- Make `agentobs settings` the primary configuration command while retaining `agentobs ui` as a compatibility
  alias.
- Deliver the existing self-contained report from a report-only, capability-protected IPv4 loopback server.
- Preserve browser-local saved views with a runtime-root-stable origin and keep a settings-launched dashboard
  alive independently until its bounded idle or hard deadline.
- Reuse one dashboard process per runtime, keep setup and demo report rendering single-pass, and retain direct
  private HTML file compatibility.

## Safety boundary

Settings and monitoring use separate routers, capabilities, instance locks, and process lifetimes. The dashboard
has no config or integration API, binds only `127.0.0.1`, verifies its private capability path and exact Host and
Origin, and identifies the owned server before reuse. Report production and delivery share one 32 MiB bound.
Each GET reopens the current report with no symlink following, private-mode and regular-file checks, and a bounded
read on the blocking executor, so an atomic collector refresh becomes visible without weakening artifact checks.

## Non-goals and remaining risk

- Claude Code and Cursor automatic collection and commercial team operation remain TODO.
- The localhost server is not the future hosted team collector or team dashboard.
- A capability-authenticated reload allocates at most the 32 MiB report bound on a blocking worker. Normal browser
  reload is bounded, but unusually high same-user concurrent reloads can create transient local memory pressure.
