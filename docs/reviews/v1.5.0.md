# v1.5.0 Release Review

This record covers the local visual configuration console release. It adds an ephemeral authenticated
loopback UI for collection, storage, and retention policy while preserving Rust-authoritative validation,
private atomic persistence, and the self-contained static report.

## Final verdict

- **Approved for merge:** exact-head local tests, GitHub CI, release build, and role-separated code,
  architecture, and design reviews passed.
- **Reviewed source:** `65eb4936f3321c6d35902d1fd1e9131bc5262bfe`.
- **Base:** v1.4.0 publication merge `982f0638de8c28efa5cf7725467dab00c7361f2c`.
- **Publication:** completed from merge commit `1c1c6d9402c9e76525564fe7d9b6727d8e110a70`.

## Delivered scope

- `agent-observability ui` starts a foreground `127.0.0.1:0` settings process and opens the browser
  without creating a persistent daemon or external request path.
- TypeScript renders responsive collection cadence, batch, heartbeat, storage, and retention policy
  visualizations with desktop, 390 px, and 320 px layouts.
- The URL-fragment capability moves into a private header, survives only same-tab reload, and is removed
  on confirmed close, invalid session, or applicable network failure.
- Rust owns defaults, strict validation, optimistic revision control, shared writer serialization, and
  private atomic replacement through a narrow local config use-case.
- HTTP headers, bodies, active connections, session duration, and graceful drain all have explicit bounds;
  filesystem work runs outside the server event loop.
- Failure states use bounded reason codes, retain shutdown retry capability, and keep actionable diagnostics
  visible. Modal focus wraps in both directions and explicit discard clears unload warnings.

## Independent review evidence

- `code-reviewer` found shutdown failure masking, stale unload dirtiness, and unbounded connection tasks.
  After fixes it reviewed exact source `65eb4936f3321c6d35902d1fd1e9131bc5262bfe` and returned `PASS`
  with no findings.
- `architect` found an overbroad absolute-lifetime claim, blocking config I/O on the server executor,
  unbounded connections, and an insufficient config responsibility boundary. After the config use-case,
  blocking executor, connection cap, and contract corrections, it returned `PASS` with status `CLEAR`.
- `designer` found config network-failure session handling and transient raw backend errors in addition to
  the earlier modal focus issue. After bounded persistent errors and lifecycle regressions, it returned
  `PASS`; desktop, mobile, and compact screenshots were inspected.

through a separately produced, versioned private canonical handoff. Team collection remains TODO.
