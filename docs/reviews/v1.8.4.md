# v1.8.4 Release Review

Status: **Candidate**. This record covers SQLite operational-error fidelity and deterministic report concurrency
coverage. Publication evidence remains empty until the exact reviewed source passes every release gate.

## Scope

- Preserve SQLite busy and other operational query failures as `StoreError::Sqlite` instead of reporting false
  schema or integrity corruption.
- Keep missing or malformed required metadata and actual schema-contract violations as
  `StoreError::SchemaMismatch`.
- Replace scheduler- and wall-clock-dependent sustained-write assertions with channel-controlled batch-write
  coverage that proves report callbacks execute after the bounded read transaction closes.
- Batch generation-fence fixture setup while preserving the 128/129/256/257 boundary cases.

## Safety boundary

This release does not change the five-second production busy timeout, rollback journal mode, transaction
boundaries, report generation fence, retry policy, durable schema, privacy projection, or stored data. The error
mapping changes only required text queries whose SQLite failures were previously collapsed into a corruption
message.

## Verification required before release

- A real exclusive SQLite lock with a zero-timeout test reader must produce
  `StoreError::Sqlite(DatabaseBusy)`; a missing required metadata row must remain `SchemaMismatch`.
- The callback/write and generation-fence tests must pass repeatedly without sleep-based overlap or elapsed-time
  thresholds.
- Workspace tests, clippy, formatting, TypeScript checks and browser smoke must pass on the exact PR head.
- Independent architecture, code and test reviews must approve the exact source.
- Exact-source automatic Codex evidence must pass before tagging.

## Non-goals

- No WAL migration, longer busy timeout, silent retry expansion or weakened corruption checks.
- No Codex compatibility-version change.
- Claude Code/Cursor automatic collection and commercial team operation remain TODO.
