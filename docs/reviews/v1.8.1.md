# v1.8.1 Release Review

Status: **Released**. This record covers the one-command Codex setup compatibility fix, the exact source
reviewed before PR promotion, publication, and a fresh install from the public release.

## Scope

- Make `agentobs setup` detect a real local Codex home or PATH executable before integration side effects.
- Connect a detected Codex installation automatically; keep `connect codex` as an advanced explicit lifecycle
  command rather than a required onboarding step.
- Preserve a valid pre-existing Codex `notify` command and expose `notify=external_preserved`.
- Add and own the agentobs notify supplement only when the slot is absent.
- Reject malformed notify values and conflicting OTEL values without modifying Codex config.
- Preserve v1.8.0 ownership snapshots and exact prior-state disconnect recovery.
- Treat nested public `--help` as help before UI/runtime dispatch.

## Safety and concurrency boundary

The ownership snapshot persists whether notify is agentobs-owned or externally preserved. Security rotation uses
that stored decision instead of inferring ownership again. Disconnect restores only against the recorded complete
connected bytes and mode, and replacement/removal repeat the exact-state check immediately before commit.
Supported agentobs lifecycle writers share a private lock. A portable filesystem CAS cannot exclude an arbitrary
process that ignores that lock and writes through an already-open descriptor in the final check/rename interval;
the public documentation states this limitation instead of promising impossible arbitration.
