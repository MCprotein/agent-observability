# v1.8.2 Release Review

Status: **Released**. This record covers the Codex `0.152.1` WebSocket telemetry compatibility fix, exact-source
review and evidence, publication, and downloaded artifact verification.

## Scope

- Treat `codex.websocket_request` as the correlated request start for Codex `0.152.1` native telemetry.
- Pair it with token-bearing `response.completed` events without allowing a correlation-less global
  `codex.api_request` event to consume the completion.
- Preserve deterministic, privacy-safe replay identity and FIFO correlation across collector restarts.
- Reject missing or zero WebSocket timestamps instead of manufacturing unstable identities.
- Pin CI and release verification to exact Codex CLI `0.152.1` while the capability remains experimental.
- Report an installed Codex version mismatch as `lifecycle_codex_version_failed` rather than a config failure.

## Safety and compatibility boundary

WebSocket replay identity is derived only from allowlisted correlation and timing values; prompt, response and
raw payload content do not enter the durable identity. Correlation state remains bounded, restart-safe and
idempotent. Legacy correlation-bearing HTTP request starts remain compatible, while correlation-less global HTTP
API events are diagnostic-only. The automatic adapter remains a macOS-only experimental boundary until the
cross-version, other-OS and other-profile verification gates pass.

## Independent review

- A two-worker Team review approved the adapter's deterministic identity, bounded FIFO correlation, atomic
  restart state and privacy boundary.
- The review initially blocked promotion because the branch base was stale, candidate wording was inconsistent,
  and exact-source release evidence was missing. The branch was rebuilt directly from current `origin/main`, and
  the documentation and workflow wording were corrected. Exact-source run `33718729920` later closed the evidence
  gate successfully.
- A final independent `code-reviewer` inspected all 20 changed files at
  `97cb911d81bd1665d5439f01280bce1a1437e00d` and approved with zero findings. It confirmed the fail-closed
  timestamp rule, framed replay identity, bounded FIFO state, atomic persistence, version alignment, privacy
  boundary and full Rust/TypeScript verification results.
- Residual risk: if upstream emits otherwise identical concurrent WebSocket starts with the same nanosecond
  timestamp and no request identifier, their deterministic replay identities can collide. The adapter cannot
  disambiguate information the source does not provide.

## Non-goals

- This release does not declare Codex `0.153.0` compatible; it verifies the exact `0.152.1` candidate.
- Claude Code and Cursor automatic connection remain TODO; their private handoff imports remain supported.
- Commercial team collection remains TODO and is not implied by this standalone adapter fix.
