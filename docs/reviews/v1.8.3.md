# v1.8.3 Release Review

Status: **Released**. This record covers safe reconciliation of later non-owned Codex configuration edits,
exact-source review and evidence, publication, and verification from the public release.

## Scope

- Let repeated `agentobs setup` or `agentobs connect codex` recover a false ownership conflict when only fields
  outside the agentobs-owned OTEL keys and optional owned notify slot changed.
- Preserve those non-owned changes across later disconnect, including changes made after agentobs created a
  previously missing Codex config.
- Keep managed-value changes, permission-mode changes, malformed TOML and unsafe paths fail-closed.
- Add the ownership-rebase scenario to the exact-source automatic lifecycle release evidence.

## Ownership and safety boundary

Agentobs owns `otel.exporter`, `otel.log_user_prompt`, `otel.environment`, and top-level `notify` only when the
snapshot records that agentobs installed it. Reconciliation compares those owned values against the connected
snapshot with exact TOML item serialization. It derives a new prior state by restoring only the old owned items
into the current parsed document, re-reads the live file, and atomically replaces only the private ownership
snapshot. It never rewrites the live Codex config during reconciliation.

`status` and direct `disconnect` do not rebase the ownership snapshot and remain fail-closed on a whole-file
mismatch; disconnect may still restore the separately owned LaunchAgent state before reporting that config
conflict. Explicit setup or connect is the config-recovery boundary. A non-cooperating process can still write after the final re-read because a
portable filesystem compare-and-swap is unavailable; that race does not let agentobs overwrite the live config
and is surfaced as a later conflict.

## Verification

- `cargo test --workspace --locked --no-fail-fast`, workspace clippy with `-D warnings`, and formatting passed.
- Targeted ownership tests cover ordinary unowned edits, external notify plus OMX hook trust state, a config that
  did not exist before connect, an unowned key inside `[otel]`, managed-value rejection, and snapshot write
  failures before and after the atomic replacement. They also cover rebase followed by managed credential
  rotation, every separately owned config field, mode changes, and malformed externally owned notify values.
- The automatic macOS lifecycle protocol now inserts a content-free external config probe after initial setup,
  requires the pre-recovery status to be conflict, repeats setup, requires byte-identical connected config, and
  requires the final disconnect to preserve the rebased probe while removing only agentobs-owned settings. The
  smoke profile passed locally with exact Codex `0.152.1`.
- `npm test` passed TypeScript generation, authored-JavaScript policy, typecheck, 27 Node tests, report browser
  smoke and settings browser smoke with no external requests, console errors or viewport overflow.
- A separate isolated CLI fixture reproduced `config=conflict`, healed it through explicit connect without
  changing the edited config hash, and preserved the unowned value after disconnect.
- The implementation at `6a167c99292ad82e9af9e4756a75b890a53efc0e` received an independent
  architecture `CLEAR` and an independent code-review `APPROVE` with zero findings. The code reviewer reran
  the Rust workspace tests, clippy, formatting, `npm test`, and `git diff --check`; the architecture reviewer
  independently inspected ownership, malformed-notify, crash, concurrency, privacy and disconnect boundaries.
- Exact-head PR CI run `33733758009` attempt 2 passed for final source
  `5e1cdb3dabd8ed60bbe3aa819f142109d4b01459`. Independent final code and test reviews approved that exact
  source with no blocking findings.
- Exact-source automatic lifecycle run `33734662082` passed five runs for the same final source before tagging.
- A later exact-head macOS CI run exposed a scheduler-dependent fixed sleep in the existing sampler exit test.
  The test now waits, within the production sampler stop timeout, for the sampler thread to finish observing the
  parent-confirmed child exit; production sampling behavior is unchanged.
- The first Linux PR attempt also exposed an existing SQLite lock-classification test flake. An exact-SHA rerun
  passed, so it did not alter this release; typed lock error reporting and deterministic concurrency coverage are
  tracked as the planned v1.8.4 follow-up rather than being misrepresented as v1.8.3 scope.

## Non-goals

- This change does not silently adopt modified agentobs-owned values.
- It does not make `status` or direct `disconnect` mutate ownership state.
- It does not claim compatibility with the locally installed Codex `0.153.0`; the release gate remains pinned to
  exact Codex `0.152.1` until separate compatibility evidence is added.
- Claude Code/Cursor automatic collection and commercial team operation remain TODO.
