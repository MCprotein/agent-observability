# v1.2.0 Release Review

This record defines the review and verification required before the standalone retention release
can be marked released. The candidate adds explicit bounded retention and private archive export to
the local-only product path without introducing a daemon, identity, endpoint, outbox, or network
dependency. Final reviewer verdicts and release evidence are recorded here only after every gate
passes.

## Delivered boundary

- `local_runtime.v2` adds strict retention limits for age, records per pass, and archive bytes while
  loading v1 configuration with explicit defaults.
- SQLite `local_state.v4` migrates v1, v2, and v3 authority and adds typed indexed retention
  selection, bounded expired-span guards, incremental vacuum mode, and applied-plan receipts.
- Retention plans select whole traces whose observations are all older than the UTC-day cutoff.
  Newer and unresolved traces remain pinned; stale incomplete traces are eligible so adapters
  without a terminal session signal can still reclaim old data.
- Apply writes and syncs a private no-overwrite JSONL archive before one immediate deletion
  transaction, then incrementally reclaims a bounded page count and rebuilds the current-record
  projection.
- The archive contract is closed and runtime-neutral. It contains sanitized durable records plus
  bounded header/footer metadata and excludes source cursors, event IDs, payload hashes, raw opaque
  IDs, prompts, outputs, and source payloads.

## Review findings resolved

- A trace that exceeds the remaining pass bounds stops the deterministic plan without being split;
  apply rejects every truncated plan so no selected prefix is partially removed. The operator must
  raise one of the bounded archive limits and create a new plan before applying.
- Candidate sizing and archive publication stream records from indexed SQLite authority. Selection
  retains only bounded trace IDs and span hashes, without cumulative archive-record or event vectors.
- Expiry guard insertion and source-input deletion use one set-wise operation instead of per-event
  or per-trace scans; only query paths that reduce repeated work keep persistent indexes.
- Old cursor replay fails closed. The newest 100,000 expired span hashes preserve semantic replay
  suppression and changed-state conflict behavior; completed receipt history is capped at 1,024,
  with receipt completion and pruning committed atomically.
- The applied-plan receipt binds recovery to the canonical archive path, plan metadata, archive
  length, and original whole-file SHA-256. A same-size internally valid archive substitution is
  rejected.
- Receipt recovery runs before selection. Pre-commit archive publication and post-commit compaction
  failures have separate retry contracts:
  a pre-commit retry uses a new path, while a post-commit retry resumes the original receipt and
  archive.
- The CLI apply path enters receipt recovery directly without a preliminary plan scan. A pending
  receipt blocks every different pass; completed receipts, dispositions, and expired-span guards
  have explicit tested caps.
- Legacy schema fixtures remove every v4-only object and restore non-incremental auto-vacuum.
  Migration bounds the legacy disposition ledger before its full rewrite, requires explicit
  workspace admitted against configured and physical free space, and preserves the old schema
  version after a failed row conversion for repair and retry.
- Archive retries hold one stable exclusive lock per archive parent and remove only strict private
  crash-left temporary names under a bounded total directory scan while the store transaction excludes
  another retention writer.
- Managed-root path canonicalization rejects archive placement inside the runtime even when the
  runtime argument itself is relative.
- The release fixture drains the fixed 64-slot ingress through one CPU execution token and one
  normalization actor. Each batch is capped at 32 records and 512 KiB, bounding the durable handoff
  to 576 KiB and total ingress-to-writer payload to about 4.6 MiB. Baseline and enabled
  supported-rate passes use the same 3 ms driver inter-arrival schedule; a separate enabled-only
  unpaced saturation pass verifies rejection, latency, bounded memory, and durable reconciliation.
  A durability barrier commits every supported accepted event before saturation begins.
  Supported CPU includes the accepted durable commit tail through barrier completion.
  Peak CPU sampling uses the profile-declared interval rather than a hidden high-frequency loop.
- CPU phase samples use process CPU-time deltas over matching wall-time intervals rather than
  process-lifetime `%CPU`. Disk evidence accounts for the complete release durable root across all
  retained run directories. Host evidence is sanitized but factual; placeholder values fail closed.
- A failed run stops the profile immediately. Worker and sampler resources are terminated/joined,
  durable payloads are removed, and the release failure manifest is retained for diagnosis.

## Required verification

- `cargo fmt --all -- --check`
- `cargo test --workspace --no-fail-fast`
- `cargo clippy --workspace --all-targets -- -D warnings`
- `npm test`, including desktop, mobile, and 4,096-span `file://` browser smoke
- `cargo run -q -p agent-observability-cli -- contracts`
- `cargo run -q -p xtask -- perf local --profile smoke --check`
- strict archive-schema compilation, migration fixtures, retention plan/apply subprocess smoke,
  privacy/legal reference scan, disabled product-network scan, browser bundle URL scan, and
  `git diff --check`

## Performance evidence

The normative five-hour local-runtime protocol must be rerun for v1.2.0 because retention changes
the local configuration and durable-store implementation. After the protocol passes, its sanitized
release manifest is retained under `docs/evidence/local/performance/`. It measures the foreground
runtime ingress boundary and does not claim native agent hook, receiver, producer, report-render,
or archive-apply latency.

## Deferred scope

- Expired records no longer contribute to subsequent reports. Correction, retraction,
  reinstatement, archive restore, and deterministic aggregate rebuild across retention remain
  unsupported until a privacy-safe contribution journal and versioned checkpoints exist.
- Automatic scheduling and archive lifecycle management are not installed; the operator chooses
  when to plan/apply and owns exported files outside the runtime root.
- Native receiver/producer integration, wider platform support, and team/commercial infrastructure
  remain Future TODO promotion work.
