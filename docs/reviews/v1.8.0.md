# v1.8.0 Release Review Draft

Status: **In Progress**. This draft records the implemented Codex automatic local collection slice and the
evidence still required before v1.8.0 can be marked `Released`.

## Review scope

- Add optional macOS Codex automatic collection through a private-CA HTTPS `127.0.0.1` OTLP/HTTP JSON receiver
  with an exact private random request header. This transport is not mTLS.
- Use `agent-turn-complete` notify only as a bounded, fail-open turn-completion supplement.
- Install and remove a runtime-root-specific LaunchAgent.
- Own only the required Codex config values and restore the exact pre-connect bytes and mode on disconnect.
- Preserve Codex, Claude Code and Cursor manual private handoff imports without daemon, login or network.
- Keep all external/team transport disabled.

## Implemented boundary

- `agentobs setup` prepares and opens the default private dashboard before connecting Codex automatic
  collection. Dashboard preparation failure prevents integration mutation; a later connection failure can leave
  the local dashboard open. `connect codex`, `status codex` and `disconnect codex` expose the lifecycle separately.
- This changes the no-argument `setup` behavior from v1.7 and earlier: it now edits the owned Codex values and
  installs a persistent local LaunchAgent. `agentobs setup ~/.agent-observability --no-open` preserves the
  explicit-root manual-import initialization path for existing scripts; automatic connection can be added later.
- The authenticated ephemeral settings UI exposes the same integration lifecycle and can open the existing
  private report without becoming the collector process itself.
- The receiver binds only IPv4 loopback. Codex and internal probes validate the private-CA server certificate and
  loopback SAN. Every health, OTLP logs and notify request must include the exact
  `x-agent-observability-token` header containing the runtime's private random 256-bit value. The Codex exporter
  contains no client certificate or client private-key field.
- OTLP/HTTP JSON requests are bounded to 1 MiB and 4096 log records. Raw notify arguments are bounded to 64 KiB,
  projected to a closed content-free wire object before settings or socket access, and use one absolute local
  connect/TLS/HTTP deadline before returning a fail-open outcome.
- Raw OTLP and tool fields may exist transiently in receiver memory during bounded decode. Raw notify exists only
  in the foreground projector and never crosses transport. Only explicitly allowlisted scalars cross the Codex
  adapter. Raw prompt/response, tool arguments/output, command, cwd, path, account identity and unknown fields are
  not persisted, logged, placed in diagnostics, projected, reported, archived or exported.
- Source-ordered observations and content-free dispositions use one SQLite transaction. Durable report and
  acknowledged generations cover ingest and retention, drive bounded startup recovery for
  `<root>/logs/agent-observability-report.html`, and expose retry exhaustion as degraded health.
- Automatic-path release evidence must include an isolated LaunchAgent lifecycle, actual Codex `0.151.0`
  `codex exec` against a content-free loopback Responses fixture, exporter construction, native OTLP acceptance,
  a private session record, exact 10-input/2-output token records, and no raw prompt persistence.
- After the real Codex gate passes, the same evidence runs synthetic Codex-shaped OTLP, the notify supplement,
  per-run tail latency, process network-byte sampling, and independent loopback endpoint checks.
- Disconnect restores the exact pre-connect LaunchAgent plist/load state, stopping and removing only a service
  created by connect, before restoring exact prior Codex config bytes/mode or removing a config created by
  connect. The complete current bytes/mode must match the recorded connected state; any intervening edit fails
  closed and remains untouched. Local observations remain.
- Exact v2 mTLS settings migration uses a durable journal. Prior settings bytes/mode and credentials survive until
  the replacement collector service and Codex config both commit; failure restores them, interrupted phases resume,
  and required cleanup plus directory synchronization errors are reported.
- The authenticated `/v1/notify` receiver accepts only the closed projected wire schema. Raw Codex notify JSON is
  valid only as foreground projector input and is rejected before receiver mapping or durable mutation.

## Explicit non-goals

- Claude Code automatic collection
- Cursor automatic collection
- OTLP/gRPC
- Agent file, credential, browser-session or private-API scraping
- Any external network destination
- Commercial team collection, query or hosted UI

The local Codex receiver is not team infrastructure. Commercial team cannot be called complete or released
before the G0-G4 approvals and evidence in `docs/TEAM_ARCHITECTURE.md` and `docs/TEAM_CONTRACTS.md` pass.
The private-CA server certificate prevents an untrusted listener from impersonating the trusted receiver to a
correctly configured client, and the exact private header rejects requests without the runtime credential. This
does not isolate a malicious process with the same OS user identity because that process can read the same `0600`
header secret or server private key and impersonate a client or receiver. Separate OS identities or a sandbox are
required for that threat model.

## Compatibility correction

The installed Codex `0.151.0` strict diagnostic confirms that the generated TOML loads, but it does not construct
the OTLP exporter. On macOS, the previous configuration with client certificate and client private-key fields
passed that diagnostic and then failed during exporter construction. The corrected product contract retains
private-CA server-authenticated HTTPS, removes client identity fields, and authenticates requests with the exact
private random header. Synthetic benchmark success is not evidence that this Codex exporter path works.

## Measurement contract correction

The first exact-revision automatic run exposed a harness mismatch rather than usable release evidence. The
20 ms p95 and 50 ms p99 limits belong to foreground hook added wall time in the normative local protocol; they
do not describe a synthetic request that includes settings reads, TLS setup, a new connection and durable
collector acknowledgement. Synthetic collector p95/p99 remain recorded per run as diagnostics until a separate
versioned collector SLO is calibrated.

The resident-memory budget is likewise p95 RSS, not the largest sampled spike. The automatic protocol now gates
each release run on RSS p95 at 96 MiB, reports peak RSS separately, and uses one reused macOS process reader for
10 ms active/report sampling instead of starting `ps` for every sample. Report projection also reuses owned
durable records and preallocates from the current count to reduce avoidable peak allocation. Because the earlier
run used the wrong latency and peak-RSS decisions and missed its declared sampling cadence, it neither approved
nor rejected this release. Corrected exact-revision run `33619463127` subsequently passed the full gate for
source `272783ff2e5bb6c7a10b224aa7821e571d6ca8f3`.
